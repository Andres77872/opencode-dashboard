# design-sync notes — Vael (opencode-dashboard)

Repo-specific facts a future sync needs. Target project: "Vael Design System"
(`ce97e376-625d-4f37-8495-e7ef61f3d1fc`).

- The design system is the app-internal library `web/src/components/vael/` —
  an app package (no dist library build). The converter runs with
  `--entry web/src/components/vael/index.ts` (the barrel), and
  `web/package.json` carries `"types": "src/components/vael/index.ts"` so the
  converter's ts-morph pass discovers components and extracts real prop types
  from source. That `types` line is inert for the app build — do not remove it.
- Components are styled with inline styles + CSS custom properties only — NO
  Tailwind classes (Tailwind is used elsewhere in the app, not in vael/).
  Tailwind is deliberately NOT bundled into the DS.
- Tokens live in `web/src/styles/tokens/*.css` (colors, typography, spacing,
  effects, base) — app-local, not a tokens package. They ship via `cfg.cssEntry`
  pointing at `web/.ds-css/vael.css`, a gitignored aggregate that
  `cfg.buildCmd` regenerates on every sync: the 5 token files + the
  non-`@import` remainder of `web/src/index.css` (the `vael-*` keyframes that
  Skeleton/IconButton-spinning/Drawer animations need, plus react-day-picker
  overrides). ALWAYS run `cfg.buildCmd` before the converter.
- Fonts: self-hosted @fontsource packages (Hanken Grotesk 400–800, JetBrains
  Mono 400–700), wired through `cfg.extraFonts` from `web/node_modules/`.
  Requires `npm ci`/install in `web/` first.
- Component groups come from one-line JSDoc `@category` tags on each component
  export in the vael source files (Atoms/Cards/Controls/Data/Charts/Overlays/
  Navigation/Feedback/Icons). New components should get the same treatment.
- `cfg.componentSrcMap` pins components that live in shared files
  (atoms/controls/charts/card/feedback) — the fuzzy finder only matches
  single-component files (Card, Icon, Tabs, Tooltip, Drawer, DataTable).
  A new component in a shared file needs a pin here too.
- No provider/context wrapper is needed — vael components are self-contained.
- `VendorChip`/`SourceStack`/`vendorMeta` take SourceID values: `opencode`,
  `claude_code`, `codex` (see `web/src/components/vael/vendors.ts`).

## Preview-authoring patterns (folded from the wave learnings)

- Vael is dark-first but preview card bodies are white: every authored cell
  wraps content in a dark canvas div (`background: var(--ink-900)`, padding,
  radius). Tiny inline atoms (chips, sparklines) read best with
  `maxWidth: 'fit-content'` canvases; thin strips need explicit widths.
- Open-state tricks that WORK in capture (keep using them): Popover — capture
  the trigger render-prop's `toggle` in a ref and call it in a mount effect;
  Tooltip — dispatch `new MouseEvent('mouseover', {bubbles: true})` on the
  wrapper span in a mount effect, center the anchor and pad the tooltip side
  ~64px so it isn't clipped. Select cannot be opened externally (Popover is
  internal) — closed-trigger cells only, open state lives on Popover's card.
- Drawer's `cfg.overrides.Drawer.viewport` is a grade-KEYED knob: changing it
  requires a full `package-build.mjs` re-stamp before `preview-rebuild`
  ([CONFIG_STALE] otherwise). cardMode/primaryStory are presentation-only.
- Charts: feed data that fills ~80% of the niceMax axis or plots look
  half-empty; AreaChart x labels clip at small widths (use short labels,
  width ≥ 340); DataTable's sort prop only draws the indicator — pass
  pre-sorted rows and a no-op onSort. Chart hover tooltips/crosshairs are
  interaction-only and not capturable — static lines/axes are the graded look.
- Skeleton captures mid-pulse (faint but visible) — expected. Notice's
  `success` tone auto-picks the info icon (only warning/danger get
  alert-triangle). ErrorState reads best composed inside a Card.
- Hover-only affordances intentionally not captured: RSpark
  crosshair/tooltip, SourceStack title tooltips, BarRow onClick hover.

## Re-sync risks

- Tooltip/Popover open-state previews depend on component INTERNALS (React
  mouseover-driven enter events; Popover's render-prop toggle). If those
  components are refactored, the open cells may silently capture closed
  states — re-grade those sheets after any controls/tooltip refactor.

- `web/.ds-css/vael.css` is generated by `cfg.buildCmd`; if the token file set
  under `web/src/styles/tokens/` changes (file added/renamed), update
  `cfg.buildCmd` to match or tokens silently drop out of the bundle.
- The `@import`-stripping step of `cfg.buildCmd` assumes `web/src/index.css`
  keeps Tailwind/token imports as leading `@import` lines; component-relevant
  globals added there in non-import form ship automatically, but new `@import`ed
  files relevant to vael components would be silently skipped.
- Font weights are enumerated in `cfg.extraFonts`; a new @fontsource weight
  import in `web/src/main.tsx` must be mirrored there.
- Playwright chromium cache on this machine: builds 1223/1228 — playwright
  1.60.0 pins 1223, 1.61.0 pins 1228; install one of those into .ds-sync
  rather than downloading a new browser.
- Converter deps for .ds-sync: esbuild, ts-morph, @types/react,
  playwright@1.61.0, and typescript@5.9.x — a bare `npm i typescript` pulls
  TypeScript 7 (native port) whose JS API breaks package-validate's .d.ts
  parse check (it reports "skipped — typescript not in node_modules").
